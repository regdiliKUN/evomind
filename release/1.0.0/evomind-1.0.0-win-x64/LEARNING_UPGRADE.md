# EvoMind 学习功能升级与验证

日期：2026-10-21。修改已直接应用于本项目，无新增运行依赖，仍使用原 `.venv` 和双击启动入口。

## 学习方向自动更换（2026-10-22 新增）

只给一个模糊方向，系统自己拆子方向、连续学、换方向、补充方向、汇总成果。

### 运行方式

```
                ┌──────────────────────────────────────────────┐
   模糊方向 ──▶ │ 拆解：模型 → 本地候选池兜底（至少 N 个合法方向） │
                └───────────────────┬──────────────────────────┘
                                    ▼
                        ┌───────────────────────┐
                        │ 选向：随机 + 避开最近K个 │◀──────────────┐
                        └───────────┬───────────┘               │
                                    ▼                           │
                     ┌──────────────────────────┐               │
                     │ 边界校验（字面 → 模型审核）│  越界则标记     │
                     └───────────┬──────────────┘  rejected 重选  │
                                 ▼                              │
                  ┌──────────────────────────────┐              │
                  │ 连续学 min(配额, 剩余上限, 100) │              │
                  │ 轮（引擎按批执行，批间不换向）  │              │
                  └───────────┬──────────────────┘              │
                              ▼                                 │
              ┌───────────────────────────────┐                 │
              │ 结算：轮次/新增/会话写入数据库   │                 │
              └───────┬───────────────┬───────┘                 │
        未满配额 ─────┘               └───── 满配额 ─────────────┘
              │                                      │
              ▼                                      ▼
     继续下一批（同方向）              达到总上限 / 用户停止 → 汇总
```

1. **拆解**：`backend/curriculum.py` 用一次模型调用把母方向拆成 N 个（默认 6）具体子方向，要求「对象 + 侧面」且可检索。模型不可用或数量不足时，用 `directions.py` 的本地候选池按「母方向：侧面」拼装补齐，拼出来的方向天然带母方向前缀。
2. **连续学**：每个子方向连续学 `rotation_rounds_per_direction` 轮（默认 100）。超过引擎单批上限 100 轮时自动拆成多批交给 `evolve.Engine`，批与批之间不重新选方向。
3. **自动换向**：满额后从剩余子方向里随机挑一个。挑选时排除最近 `rotation_recent_window`（默认 3）个方向；候选先过边界校验，越界的标记为 `rejected` 并重选，最多试 8 个。
4. **边界校验**：先做便宜的字面包含判断（本地拼装方向必然命中）；不命中再让模型以「严格属于母方向语义范围」为标准判定，拿不准判为不属于。判定结果按 (母方向, 候选) 缓存，避免重复调用。审核本身调用失败时放行并记录原因——拆解已经被同一母方向约束过，不能因为一次审核超时让整个轮换空转。
5. **补充**：池子空了先补充新子方向（同样过边界校验），补不出来才把已学过的重新放回待学；最后还有本地拼装兜底，保证学习不中断。子方向池最多扩到「首轮数量 × 6」，防止无限膨胀。
6. **轮次结算**：用引擎新增的 `completed` 计数（真正跑完的轮数），而不是 `round`（正在跑第几轮）。中途停止时 `round` 会多算一轮，按它结算会让配额和进度全错。
7. **手动跳过**：不想学某个子方向时点「跳过当前方向」，当前这一轮跑完就换下一个，剩余轮次不再学；跳过的方向按已学轮次计入汇总（标注「未学满」）。
8. **预览可沿用**：先「预览子方向」再开始，会沿用预览的那一批，不会因为模型重新生成而变成另一组。
9. **暂停 / 恢复 / 结束**：暂停置位后让当前这一轮跑完再停（不会丢正在读的页面），恢复从剩余轮次继续；结束立即结算并输出汇总。进程重启后库里 `running` 的僵尸任务由 `recover_stale()` 标为中断。

### 状态与汇总

三张表：`curriculum_runs`（任务：母方向、配额、总上限、状态、汇总文本）、`curriculum_directions`（每个子方向：状态、轮次、新增条数、首末轮次）、`curriculum_switches`（切换历史：从哪到哪、原因、第几轮）。

汇总按方向列出轮次、新增知识点条数，以及该方向最近 3 条结论作为代表；同时写入 `curriculum_runs.summary` 供重启后查看。

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/rotation` | 当前进度、子方向列表、切换历史、最近 5 次任务 |
| POST | `/api/rotation/start` | `{seed, rounds_per_direction?, total_rounds?, subdirection_count?, items?}`；带 `items` 就沿用预览结果 |
| POST | `/api/rotation/pause` · `/resume` · `/stop` | 暂停 / 恢复 / 结束并汇总 |
| POST | `/api/rotation/skip` | 跳过当前方向，立刻换下一个（仍走边界校验与最近窗口） |
| GET | `/api/rotation/summary` | 成果汇总 + 纯文本 + 最近 10 次任务；`?format=text` 直接返回文本 |
| POST | `/api/rotation/plan` | 只预览拆解结果，不启动 |

`/api/status` 增加 `rotation` 字段和 `direction_rotation` 能力标记；`/api/learn/stop` 现在同时停掉轮换（同一个学习引擎，否则会被立刻拉起来）。

示例：

```bash
# 先看会拆成哪些子方向（不启动学习，约 5-15 秒）
curl -X POST http://127.0.0.1:8765/api/rotation/plan \
  -H 'Content-Type: application/json' \
  -d '{"seed":"光固化 3D 打印","count":6}'

# 启动：每个子方向 100 轮，总上限 300 轮
curl -X POST http://127.0.0.1:8765/api/rotation/start \
  -H 'Content-Type: application/json' \
  -d '{"seed":"光固化 3D 打印","rounds_per_direction":100,"total_rounds":300,"subdirection_count":6}'

curl http://127.0.0.1:8765/api/rotation            # 进度：当前方向、剩余轮次、子方向状态、最近任务
curl -X POST http://127.0.0.1:8765/api/rotation/pause
curl -X POST http://127.0.0.1:8765/api/rotation/resume
curl -X POST http://127.0.0.1:8765/api/rotation/stop   # 结束并返回各方向汇总
```

### 排障对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 状态一直「学习中」但轮次不涨 | 单轮要检索+抓取+提炼，2–4 分钟属正常 | 看事件流走到哪一步；停在「多源检索」多半是搜索源被限流 |
| 反复出现「丢弃越界子方向」 | 模型拆解滑向相邻领域，审核在拦 | 属预期行为；若一直补不进，说明母方向太宽，换更明确的领域名 |
| 显示「等待其他任务结束」 | 学习引擎被手动学习/书库/OCR 占用 | 等对方结束会自动继续，不计失败；也可先停掉对方 |
| 连续两次「没能推进」后暂停 | Ollama 未运行或网络不可用 | 启动 Ollama 后点「恢复」，会从剩余轮次继续 |
| 汇总里某方向只有 0 条 | 该方向资料被限流或内容重复 | 不影响其他方向；可对该方向单独再学 |
| 重启后看不到当前进度 | 进程重启会中断任务（内存态丢失） | 汇总与历史仍在数据库里；重新启动即可 |


### 与既有任务的互斥

`tasks.busy_reason()` 增加「方向轮换」一项，与学习、炼化、书库、OCR、微调共用准入。轮换内部调用 `evolve.engine.start(..., _internal=True)` 走内部通行证；`exclusive` 装饰器现在会先摘掉这个参数再转发，避免目标函数收到不认识的键。

| 参数 | 默认 | 范围 |
|---|---|---|
| `rotation_rounds_per_direction` | 100 | 1–2000 |
| `rotation_total_rounds` | 300 | 1–100000 |
| `rotation_subdirection_count` | 6 | 2–20 |

## 重复清理与交互修复

- 知识库顶部新增「一键清理重复项」和「撤销上次清理」。自动处理同方向、结论和补充内容一致的条目，选择较高可信度条目保留，其他记录连同向量、书籍标记和来源逐条归档。可完整恢复；原知识引用仍可通过归档打开。不同数字、否定条件、代码大小写/缩进及不同向量版本会保留，不按相似度自动删除。
- 「随机选一个方向」仅填写方向，不启动学习或改变轮数。用户选择轮数后独立点击「开始进化学习」；浏览器验证提交16轮成功。
- 一键书籍炼化的 Not Found 来自运行中的旧后台没有加载新接口。新后台增加版本与能力标记，界面遇到旧接口也会给出中文更新提示。
- 最新验证：102项后端、23项前端通过；浏览器验证清理/撤销、归档来源、仅随机选择、手动16轮启动、一键炼化及无API 404。测试清理只在隔离样本库执行，未自动清理用户知识库。

## 后续新增：一键炼化全部书籍

在「知识库」点击 **一键炼化全部书籍** 即可，无需选择方向。系统识别所有已入库的书籍知识，按书籍及方向隔离、每批最多60条处理，遍历全量，不受原“最近120条”限制。当前库识别到17,020条书籍知识，首次计划367批；这是任务计划，并未在验证时自动执行整库任务。

- 进度显示已处理/总量、当前书籍、批次、当前归纳阶段、跳过条数和本次保存批数。
- 每批结果和完成记录在同一事务中保存。停止或重启程序后，再次点击会跳过已完成且内容未变化的知识；新增或修改的内容会重新处理。
- 单批失败保留其他成功结果，再次点击可重试；连续3批失败会停止并提示检查模型。
- 历史结果显示书名并支持上一页/下一页，原始知识和出处继续保留。
- 仍遵循重任务互斥；其他学习、OCR、导入或训练正在运行时会明确提示等待。

追加验证：10项后端回归覆盖超过120条、书籍隔离、网页排除、停止续做、失败重试、内容变化检测、事务回滚及结果分页；3项前端回归覆盖一键范围、重复点击、状态和分页。全套现为94项后端、22项前端通过。真实模型在独立库对6条既有书籍知识生成4个核心，约6.35秒；再次点击跳过全部6条，未重复调用模型。浏览器验证了按钮、范围重置、进度、引用、分页及390px布局。

## 如何使用

1. **随机方向**：进入「自主进化」，填预设领域（例如 ZBrush），点「刷新方向」获得6个候选。点击候选或「随机选一个方向」填写方向，调整轮数后再点「开始进化学习」。换领域后会先重新刷新。ZBrush 内置30个具体主题，其他领域由通用学习维度组合，方向刷新不依赖模型联网或推理。
2. **持续自学**：在原持续开关下设置间隔及每次轮数，保存后开启。空闲间隔1–30秒，新配置默认15秒；旧20分钟配置自动迁移为30秒。从上一段学习结束计时，当前学习本身仍可能耗时数分钟。关闭开关会取消后续调度；点学习「停止」会关闭调度，并让当前请求完成后收尾。
3. **二次炼化**：进入「知识库」，先用方向筛选选定范围，再点「炼化当前范围」。最多处理最近120条，全部方向会按主题分别炼化。结果独立保存；展开历史可查看核心内容、压缩比例、原知识和来源原文。原始知识不覆盖、不删除。停止炼化会等待当前模型请求结束。
4. **方向自动更换**：进入「自主进化」最下面的面板，填一个大致的领域（如「光固化 3D 打印」），设好每方向轮数、总轮次上限和子方向数量。可先点「预览子方向」看拆解结果，再点「开始自动轮换」。运行中可暂停 / 恢复；点「结束并汇总」输出各方向的轮次与新增条数。

## 搜索与质量改进

- 通用搜索与专用来源并行，不再因为论坛或百科出现少量结果就跳过网页搜索。
- 增加 ZBrush、Blender 官方文档目录直连。在搜索引擎受限时仍能按具体操作检索官方目录。
- 解码 Bing 跳转链接，清理跟踪参数并去重；按查询匹配、官方来源及域名分散排列候选。
- 规划使用短查询、官方站点限定和中文补充。历史查询及复盘缺口跨学习任务保存。
- 长文按相关段落选择最多3块提炼，每条候选都需提供能在正文中找到的原文摘录，再进行一次结论与证据核对。炼化核心同样核对原知识支持程度。
- “成功抓取”与“已学习”分开记录；提炼失败或零产出可在后续任务重试，完成状态按方向区分。日志展示读取失败、提炼失败、核对与重复情况，不再将零产出解释成已学透。
- 模型及数据集发现与知识资料检索分开，减少无关资源占用阅读名额。

## 冲突与交互修复

- 学习、炼化、导入、书库扫描/解析、OCR、训练集生成和微调共用任务准入检查。持续调度会等待其他重任务，手动冲突会收到明确提示。
- 后台线程启动前先占位；线程启动失败或异常退出会释放相应状态，避免重复点击竞态或按钮永久锁住。
- 扫描书库在后台执行；请求立即返回，进度通过原书库界面显示。
- 开始学习被拒绝时保留原事件流；连续点击只提交一次。方向刷新丢弃过期响应，炼化轮询保持展开状态。
- 知识库的方向选择来自全部主题，不再受当前60条列表限制。
- 启动器先同步检查 Ollama 的实际在线状态，避免首次缓存未就绪时重复尝试启动。
