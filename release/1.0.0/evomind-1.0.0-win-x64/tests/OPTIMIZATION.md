# 检索性能与可靠性优化 · 2026-10-18

本轮在 `c210d97` 的学习空转修复之上整合，保留已有的主题归一化、导入中断恢复、启动器模型识别和测试隔离。

## 已修复的问题

| 问题 | 修复后的行为 |
|---|---|
| 检索固定截取前 20 条，`k=45` 实际只返回 20 条 | 按请求取前 k 条，上限 1000 |
| 先全局截断再过滤主题，目标主题可能没有结果 | 排名前过滤主题；API 同时传递关键词与主题 |
| 不同维度或损坏向量使整个检索报错 | 按维度缓存，跳过损坏、非有限或零向量；无效新向量拒绝入库 |
| 每次检索重新归一化整个矩阵并全量排序 | 缓存单位向量，用部分选择后仅排序命中结果 |
| 并发去重检查与写入分离，重复知识可能同时入库 | 将检查、提交与缓存失效放在同一写锁中 |
| 删书后残留缓存阻止再次导入 | 删除知识点时同步清理缓存，删除事务与写锁保持一致 |
| 导入书籍的来源关联事务延续到下一次入库 | 每条关联及时提交，避免与并发写锁互等 |
| 配置并发更新丢字段、写失败后缓存与磁盘不一致 | 串行读改写，同目录临时文件原子替换；替换成功后再更新缓存 |
| 非法配置进入后台任务后才报错 | 保存时校验类型、有限数值及范围，API 返回 422；旧无效字段逐项回退默认值 |
| 并发启动学习产生两个会话，Ollama 离线留下 running 会话 | 串行启动；离线或线程启动失败时结束会话并释放运行状态 |
| 自动刷新清空搜索，旧请求可能覆盖新结果 | 保持提交的搜索条件、丢弃过期响应；状态轮询避免重叠并跳过隐藏页面 |
| 快速测试仍访问网络，且配置写入用户目录 | 配置与数据库均使用临时目录；快速模式使用确定性测试向量并跳过外部探测 |

知识列表总数改为单独的 SQL COUNT，避免为获取条数而递归扫描模型下载目录。负数事件条数也不再返回整张日志表。

## 性能测量

`python tests/benchmark_retrieval.py [checkout]` 使用固定随机种子 42，创建 **10000 条 × 1024 维**向量。预热缓存后查询 30 次，设置单线程 BLAS，统计中位数：

| 实现 | 中位耗时 |
|---|---:|
| 优化前 `249dc90` | 26.851 ms |
| 本轮优化后 | 1.249 ms |

该场景约加速 **21.5 倍**，前 8 条结果 ID 与顺序一致。这仅衡量缓存已预热的向量检索和 SQL 结果读取，不包含 Ollama 向量生成、缓存首次构建、网页检索、OCR 或训练耗时，不代表整个应用同等加速。

## 适用边界

- 检索仍是精确的全量相似度计算，缓存仍驻留内存；本轮未引入 ANN 索引。
- 不同模型即使维度相同也可能属于不同语义空间。现有表没有记录向量模型身份；切换向量模型后应重新生成旧知识的向量。本轮的维度隔离解决崩溃，不等于完成向量迁移。
- 快速测试的哈希向量只用于验证写入、去重及控制流程，不能评估真实语义质量；真实向量链路另由本机 Ollama 检查覆盖。
- 未运行完整网络学习循环、GPU 微调、真实模型下载或整本书 OCR；这些流程有时间、资源及外部服务依赖。
